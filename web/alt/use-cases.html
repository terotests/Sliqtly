Use case 01

Themable Markdown slides for product presentations

The situation

A product team has to pitch Kokkaa, a cooking app, to investors next week and to customers at launch. The story is the same; the look is not. Last time the deck was rebuilt twice by hand: once in the investor template, once in the brand colours.

How Sliqtly does it

The assistant writes the deck as plain Markdown: a heading per slide, a ```stats block for the numbers, ```process for how it works, ```cards for the plans and ```timeline for the launch.

The theme lays every slide out. Pearl gives the soft light look; changing one word to midnight turns the whole deck dark with no slide touched. The figures are drawn as shapes, so they stay editable in the PowerPoint export.

What you get

Two decks from one text: same words, same slides, a different look in one line.

Use case 02

Multi-agent product development documentation storage

The situation

The Hull Runner team has Claude in a chat writing the product brief, Claude Code keeping the architecture and API pages in step with the code, a Cursor agent writing the test plan, and two people editing release notes. Before, each agent wrote its own file and nobody knew which copy was current.

How Sliqtly does it

Everything lives in one Sliqtly notebook. Each assistant connects over MCP, says which slides it is about to change (begin_work) and gets told when someone else already holds them, so two agents never write over each other.

Every save is a version. When a person edits by hand, the next assistant is told exactly what changed, and a comment on a slide comes back to the assistant as its next task.

What you get

One current copy of the product docs, written by several agents at once, with the history of who changed what.

Use case 03

User interface prototyping and development environment

The situation

The Kokkaa designers want feedback on the recipe flow before anyone builds it. Static screenshots in a deck don't show what happens on a tap, and a separate prototype tool means another link, another login and a copy of the screens that drifts.

How Sliqtly does it

The flow is a Mermaid diagram on one slide. On the next, a small program written in TSX runs inside the slide as a clickable phone: tap a recipe, start cooking, watch the timer. It runs in the share link too, so reviewers try it where they read the notes.

When feedback comes in, the assistant changes the one .tsx file and the prototype in the deck updates. Findings go on the slide after it.

What you get

The flow, a working prototype and what testers said, in one deck everyone already has open.

Use case 04

Planning and implementation notebook

The situation

Search in the Kokkaa app is the big item for Q4. The plan was in a doc, the milestones in a roadmap tool, the status in chat threads, and the weekly meeting started with ten minutes of finding the latest version.

How Sliqtly does it

One notebook topic holds the goal and scope, the milestones as a timeline, the implementation steps and a status table. Claude Code can update the status row when its PR merges; people comment on a row to hand the next step to an assistant.

Because every version is kept, the team can see how the plan changed between weeks, and the same topic is presented in the weekly meeting as it is.

What you get

Plan, progress and history in one place that both people and assistants keep up to date.

Use case 05

Quality assurance documentation

The situation

Release 2.4 needs a sign-off. The test results are in CI logs, the defects in a tracker, and the fix for the blocking bug in a pull request. The release manager wants one page that says whether it is safe to ship.

How Sliqtly does it

After the test run, a QA assistant writes the report: the numbers as a stats figure, pass and fail by suite as a chart, the open defects as a table and the fix for the blocker as a diff with the changed characters marked.

Sliqtly can also read a GitHub pull request directly and build a review deck from it, so the fix and its explanation stay together.

What you get

A test report the release manager reads in two minutes, rebuilt after every run.

Use case 06

Process workflow presentations

The situation

A warehouse is about to change how it handles orders. Before anything changes, everyone needs to agree on how it works today: the steps, where the decisions are made, and what is good and bad about it.

How Sliqtly does it

The steps are a ```process figure, the decisions a Mermaid flowchart written in a few lines of text, and the current state a SWOT. While presenting, the diagram can be toured node by node.

Because it is text, the assistant redraws the whole flow after a workshop from the notes, instead of someone moving boxes by hand.

What you get

A shared picture of the process that is quick to change when the process changes.

Use case 07

Charts and visual themes

The situation

The monthly growth review has the same five charts every time. Someone exports them from the analytics tool, pastes them into slides and fixes the colours by hand so they match.

How Sliqtly does it

Each chart is a small Vega-Lite spec in the deck: an area chart of users, a donut of channels with the numbers beside it, bars with value labels. The theme colours them, so the charts always match the slides.

A chart can read a CSV, an Excel sheet or a Google Sheet, so next month the assistant changes the data and the charts follow.

What you get

Charts that match the deck and update from the data instead of being pasted again.

Use case 08

Visualising financial documents and Excel sheets

The situation

Finance keeps the 2027 budget in an Excel workbook. The board wants slides, but every copy-paste from the workbook is a chance for a number to go stale or wrong.

How Sliqtly does it

The workbook goes into the deck as it is. Each sheet can be read by name: a ```sheet block shows the quarters table (and can be opened and edited while presenting), and the charts read the same sheets.

When finance sends a new version of the workbook, the table and charts redraw from it; nothing is retyped.

What you get

Board slides that show the numbers in the workbook, not a copy of them.

Use case 09

3D objects in product presentations

The situation

Kide is a kitchen speaker that hasn't been manufactured yet. Photos don't exist, renders take a designer a week, and a flat drawing doesn't show the light ring on top.

How Sliqtly does it

A slide program places a 3D model beside the slide's text: cylinders, a metal top and a glowing ring, written as a few lines of React Three Fiber style JSX. It turns slowly while the presenter talks, and the ring pulses like the timer would.

A glTF model from a CAD tool can be placed the same way, and the world can be exported back out as glTF.

What you get

A product people can see from every side, in the same deck as its specs.
