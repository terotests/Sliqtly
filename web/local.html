Sliqtly

Sliqtly Personal · Linux, macOS, Docker

Run Sliqtly locally.

The Personal server runs on your own computer: the MCP endpoint your agent writes presentations through, and a viewer that plays them in your browser. It runs as a background service and keeps the presentations on your own disk: data stays between your machine and your agent. Out of the box only your own computer can connect.

How it keeps data Ubuntu / Debian (.deb) macOS (Homebrew) Docker Networks Firewall Data and backups

How the local server keeps data

  • No sign-in. Everyone who can reach the server is the same user: every connected agent can read, change and remove every presentation, from any conversation. A new conversation keeps working on the old presentations by their links.
  • Nothing expires. Presentations and their files stay until you delete them. (The cloud demo at sliqtly.com removes anonymous presentations some days after their last change.)
  • You look after it. Cleaning up, backups and who can reach the server are yours: it is an open store for everything you make. Ask your agent to tidy up, or delete a presentation with curl -X DELETE http://localhost:8080/api/shares/<id>.

Keep the server to this computer (the default) unless you trust everyone on the network, since anyone who reaches it can do the same; see Networks.

1. Install

Ubuntu and Debian

Download (.deb, amd64) ARM (arm64) 

curl -fLo /tmp/sliqtly-personal.deb https://sliqtly.com/download/sliqtly-personal_amd64.deb
sudo apt install /tmp/sliqtly-personal.deb

On an ARM computer (a Raspberry Pi with a 64-bit system, an ARM laptop) take sliqtly-personal_arm64.deb. The service starts right away and again at every boot.

macOS (Homebrew)

brew install terotests/sliqtly/sliqtly
brew services start sliqtly         # now and at every login

Apple silicon and Intel Macs both work.

Docker

docker run -d --name sliqtly --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v sliqtly-data:/data -v sliqtly-backup:/backup \
  ghcr.io/terotests/sliqtly-personal:latest

The image runs on linux/amd64 and linux/arm64, so Docker Desktop on a Mac or Windows works too. The presentations are in the sliqtly-data volume and survive updates. 127.0.0.1 in -p keeps it to this computer; see Networks before you change it.

Then open http://localhost:8080/: the page lists your presentations, and each one plays in the viewer.

2. Connect your agent

The MCP endpoint is http://localhost:8080/mcp.

Claude Code

claude mcp add --transport http sliqtly http://localhost:8080/mcp

Cursor (~/.cursor/mcp.json)

{
  "mcpServers": {
    "sliqtly": { "url": "http://localhost:8080/mcp" }
  }
}

VS Code (.vscode/mcp.json)

{
  "servers": {
    "sliqtly": { "type": "http", "url": "http://localhost:8080/mcp" }
  }
}

Claude Desktop, which starts its servers as programs (needs Node.js)

{
  "mcpServers": {
    "sliqtly": { "command": "npx", "args": ["-y", "mcp-remote", "http://localhost:8080/mcp"] }
  }
}

Agents that run in their vendor's cloud (claude.ai connectors, ChatGPT) cannot reach a server on your own computer. Use a local client, or the hosted service at https://sliqtly.com/mcp.

3. Use the service

Ubuntu and Debian (systemd)

systemctl status sliqtly          # is it running, and since when
sudo systemctl restart sliqtly    # after changing the settings
sudo systemctl stop sliqtly       # stop it for now
sudo systemctl start sliqtly
sudo systemctl disable sliqtly    # do not start it at boot
sudo systemctl enable sliqtly     # start it at boot again
journalctl -u sliqtly -f          # follow its log

macOS (Homebrew)

brew services list                  # is it running
brew services restart sliqtly       # after changing the settings
brew services stop sliqtly          # stop it, and do not start it at login
brew services start sliqtly
tail -f "$(brew --prefix)/var/log/sliqtly.log"

Docker

docker ps --filter name=sliqtly     # is it running
docker restart sliqtly
docker stop sliqtly                 # stays stopped until docker start
docker start sliqtly
docker logs -f sliqtly

4. Choose the port

The server listens on 8080. To use 8090 instead:

InstallChangeThen
.debPORT=8090 in /etc/sliqtly/sliqtly.envsudo systemctl restart sliqtly
HomebrewPORT=8090 in $(brew --prefix)/etc/sliqtly/sliqtly.envbrew services restart sliqtly
Dockerthe left side of -p: -p 127.0.0.1:8090:8080remove the container and run it again (the volumes keep the presentations)

Then open http://localhost:8090/ and point your agent at http://localhost:8090/mcp. A port below 1024 needs extra rights; pick one above it. If the port is taken, the log says so and the server does not start.

5. Networks

The server decides which network interfaces it listens on. Pick the row that matches where other people are; the default, this computer only, needs nothing.

Who should connect.deb and HomebrewDocker
Only this computerSLIQTLY_LISTEN=local (the default). It listens on 127.0.0.1 and ::1 only, so on a café or hotel Wi-Fi nobody else sees it.-p 127.0.0.1:8080:8080
Computers on a wired LAN (office, home cable)SLIQTLY_LISTEN=wired. It listens on the Ethernet interfaces only and takes connections only from their subnets. Wi-Fi, phone tethering, VPNs and virtual interfaces stay closed, and plugging a cable in or out takes effect without a restart.-p 192.168.1.10:8080:8080, with this computer's LAN address
Computers on a Wi-Fi you trust (your home)SLIQTLY_LISTEN=network with SLIQTLY_ALLOW=192.168.1.0/24 (your home network's range). wired never opens Wi-Fi on purpose.as above, with the Wi-Fi address
The public internetDo not open the port directly. Put a reverse proxy with a real HTTPS certificate in front (below), keep Sliqtly on local, and set SLIQTLY_TOKEN.

Whenever other computers connect, also set a token, so only your own agents can write:

SLIQTLY_TOKEN=a-long-random-secret      # e.g. from: openssl rand -hex 24

Their agents then add the header Authorization: Bearer a-long-random-secret (Claude Code: --header "Authorization: Bearer …"), and use this computer's name or address instead of localhost, e.g. http://my-pc.local:8080/mcp.

The token protects the MCP endpoint only. Anyone who can reach the server can open the presentations on it, so open it only on a network you trust, and never on a public Wi-Fi.

In Docker, the server sees connections through Docker's own network, so choose who reaches it with the -p address and the firewall rather than SLIQTLY_ALLOW.

On the internet, behind a proxy

For a server others reach over the internet, let a web server with a real certificate take the connections. With Caddy and a domain pointing at the machine, /etc/caddy/Caddyfile is:

slides.example.com {
    reverse_proxy 127.0.0.1:8080
}

and in sliqtly.env: SLIQTLY_LISTEN=local, SLIQTLY_URL=https://slides.example.com, SLIQTLY_TOKEN=…. Only ports 80 and 443 are then open to the internet; 8080 stays closed. The Personal license allows this for your own use, not as a service for another organization.

6. Firewall

With local nothing needs opening. When other computers connect, open the port only to the network they are on.

Ubuntu and Debian (ufw)

sudo ufw allow OpenSSH                                          # if you log in over SSH
sudo ufw allow from 192.168.1.0/24 to any port 8080 proto tcp   # your LAN only
sudo ufw enable
sudo ufw status numbered

Behind a proxy, open 80 and 443 (sudo ufw allow 80,443/tcp) and not 8080.

macOS

The firewall is in System Settings → Network → Firewall. With it on, macOS asks once whether sliqtly-server may accept incoming connections when the server first listens beyond this Mac; answer Allow on a network you trust. With local it never asks.

Docker

Docker's published ports go around ufw and firewalld: a container started with -p 8080:8080 is open to every network the computer is on, whatever ufw status says. Always give -p an address (127.0.0.1 or the LAN address), or filter in the DOCKER-USER chain:

sudo iptables -I DOCKER-USER -p tcp --dport 8080 ! -s 192.168.1.0/24 -j DROP

7. Where the data is, and backups

Everything the server keeps is in one data folder, in two SQLite databases:

FileWhat is in it
sliqtly.dbThe presentations, their versions and comments, and the server's settings.
blobs.dbThe files: pictures, Excel and CSV data, drawings.

Next to them are small working files (-wal and -shm files while the server runs). The folder is:

InstallData folderDaily backups
.deb/var/lib/sliqtly/var/lib/sliqtly-backup
Homebrew$(brew --prefix)/var/sliqtly$(brew --prefix)/var/sliqtly-backup
Docker/data (volume sliqtly-data)/backup (volume sliqtly-backup)

SLIQTLY_DATA and SLIQTLY_BACKUP move them. Do not copy the databases while the server runs: a copy taken mid-write can be broken. Either stop the service and copy the whole folder, or use the built-in backup, which is safe beside a running server.

The built-in backup

The server takes a backup at start when the last one is older than a day, then every day (SLIQTLY_BACKUP_EVERY, e.g. 12h), and keeps the last 3, 14 daily and 8 weekly ones (SLIQTLY_BACKUP_KEEP). Backups are incremental: an unchanged picture is stored once. An empty SLIQTLY_BACKUP turns them off. Mount another disk at the backup folder to keep it apart from the data.

# see and check the backups (.deb; Homebrew without sudo and with its folder)
sudo sliqtly-server backup list   -repo /var/lib/sliqtly-backup
sudo sliqtly-server backup verify -repo /var/lib/sliqtly-backup -deep

# a backup now, e.g. to a USB disk; safe while the server runs
sudo sliqtly-server backup run -data /var/lib/sliqtly -repo /media/usb/sliqtly-backup

# restore into a new folder (never over the live one); it is checked as it is written
sudo sliqtly-server backup restore -repo /var/lib/sliqtly-backup -id latest -into /var/lib/sliqtly-restored

# drop old backups by the same rule the server uses
sudo sliqtly-server backup prune -repo /var/lib/sliqtly-backup -keep last=3,daily=14,weekly=8

To look at a restored folder before using it, run a second server on it: sliqtly-server -data /var/lib/sliqtly-restored -port 8099. To switch to it, stop the service, move the old data folder aside, move the restored one into its place and start the service again.

In Docker the same commands run inside the container:

docker exec sliqtly /sliqtly-server backup list -repo /backup
docker exec sliqtly /sliqtly-server backup run -data /data -repo /backup

8. Update or remove

.deb

Download the newest package and install it the same way; the service restarts by itself.

sudo apt remove sliqtly-personal    # stops it; the presentations stay
sudo apt purge sliqtly-personal     # also removes /etc/sliqtly

Homebrew

brew upgrade sliqtly && brew services restart sliqtly
brew services stop sliqtly && brew uninstall sliqtly   # the presentations stay in $(brew --prefix)/var/sliqtly

Docker

docker pull ghcr.io/terotests/sliqtly-personal:latest
docker rm -f sliqtly                # then the same docker run as above
docker volume rm sliqtly-data sliqtly-backup   # only to delete the presentations too

Removing never deletes the presentations by itself; delete their folder or volume yourself if you want them gone.
